# Исходные измерения открытия дневника

27 октября 2026, исходный код опубликованного `0855379`. При съёмке исходного
профиля код приложения не менялся. Затем по подтверждённой задержке подготовлен
локальный пакетный импорт; его результат приведён в конце отчёта.

## Среда и границы

- Node.js 24.19.0 на текущем ПК; встроенный Chromium для браузерного прогона.
- Синтетический снимок: 8 недель / 240 уроков либо 36 недель / 1080 уроков,
  шесть уроков в день, два предмета, числовые пары `9/9` и домашние задания.
- Для браузера собрана отдельная минифицированная версия с теми же Vite inputs,
  `VITE_APP_MODE=local`, пустой process-only Supabase-конфигурацией и base `/`.
  Сервер отдавал её по домашней LAN. Снимок передавал синтетический desktop bridge
  с обычными проверками origin/source/requestId; установленное расширение не нужно.
- Временные инструменты, снимки и сборка находятся только в игнорируемой `.vite/`.
  Плагин измерений добавлял отметки к копии `script.js` при отдельной сборке;
  исходный composition root, store, production build и публичный сайт не правились.
- Маркеры показывают готовность DOM после `init()`. Скрытая вкладка не дала paint
  entries, поэтому эти числа не являются FCP/LCP или временем видимого кадра Safari.
- Это одиночные контрольные прогоны без ограничения CPU/сети. Реальный iPhone,
  внешний интернет, Auth, device RPC и чтение облачного снимка здесь не измерены.
  Встроенный снимок увеличивает HTML, поэтому сетевой результат нельзя напрямую
  переносить на production. Браузерный кеш ресурсов отдельно не сбрасывался.

## Подтверждённая повторная работа

В [script.js](../script.js) `importJournalEntries()` вызывает
`store.saveJournalEntry()` для каждого импортированного урока, в том числе при
повторном открытии неизменившегося дневника. Это происходит до `init()`.

В [journal-store.js](../js/journal-store.js) каждый такой вызов:

1. Читает, разбирает и нормализует целый документ через `getDocument()`.
2. Ищет прежние сущности урока в коллекциях и заменяет их.
3. Сериализует и сохраняет целый документ через `saveDocument()`.

Число записей равно числу уроков. По мере роста документа возрастают стоимость
каждой записи и суммарная сериализация. При повторном открытии документ уже
заполнен целиком, поэтому обработка может быть дороже первого импорта.

### Изолированный Node-прогон

Общий `adaptESchoolsSnapshot()` и существующий `createJournalStore()`, хранилище
в Map. Таким образом, здесь измеряется прежде всего CPU разбора, нормализации и
сериализации, а не дисковая задержка браузерного localStorage.

| Уроков | Проход          | Адаптация снимка, мс | Импорт в журнал, мс | Чтений / записей |
| ------ | --------------- | -------------------- | ------------------- | ---------------- |
| 240    | Пустой документ | 40                   | 123                 | 240 / 240        |
| 240    | Повторный       | 40                   | 455                 | 240 / 240        |
| 1080   | Пустой документ | 45                   | 2910                | 1080 / 1080      |
| 1080   | Повторный       | 45                   | 10502               | 1080 / 1080      |

Адаптация выполнялась один раз на набор; значение в повторной строке приведено

### Полное открытие в браузере

| Набор и состояние               | Модули готовы, мс | Данные готовы, мс | Импорт журнала, мс | DOM готов после init, мс |
| ------------------------------- | ----------------- | ----------------- | ------------------ | ------------------------ |
| 240 уроков, повторное открытие  | 60,8              | 99,1              | 360,6              | 539,4                    |
| 1080 уроков после набора из 240 | 70,3              | 163,8             | 2678,8             | 3111,8                   |
| 1080 уроков, повторное открытие | 51,3              | 128,4             | 8305,7             | 8701,9                   |

Колонки «готовы» отсчитываются от начала навигации, импорт журнала — отдельная
длительность между маркерами. Второй сценарий не является чистым холодным запуском:
локальный документ уже содержал первые 240 уроков. На повторе 1080 уроков участок
импорта занимает примерно 95% времени до готовности DOM в этом прогоне.

В браузерном повторе 1080 уроков зарегистрировано 1080 записей и суммарная длина
переданных в них строк 607096080 кодовых единиц UTF-16. Это счётчик повторной
сериализации; размер последнего сохранённого документа существенно меньше.

## Стартовые ресурсы опубликованной сборки

Посчитаны JS и CSS из script/modulepreload/stylesheet ссылок `dist/index.html`.
Gzip рассчитан локально; это оценка размера файлов, без HTTP overhead и кеша.

| Ресурсы    | Количество | Исходный размер, байт | Gzip, байт |
| ---------- | ---------- | --------------------- | ---------- |
| JavaScript | 9          | 531370                | 162982     |
| CSS        | 1          | 161595                | 29519      |

Крупнейший стартовый JS — Supabase SDK/сервисы, 245286 байт. Возможность отложенной
загрузки требует анализа Auth и облачных сценариев. На локальной LAN в этом
контрольном примере CPU импорта значительно дороже загрузки/инициализации модулей;
это не доказывает тот же порядок на медленном мобильном интернете.

## Неизмеренные сетевые ожидания

Код-аудит подтверждает ожидание site status до инициализации UI с пределом 5 с,
затем подготовку Auth/device access с собственными пределами. Это верхние тайм-ауты,
не наблюдённые задержки. Порядок owner/linked checks и инвалидацию кеша нельзя
ослаблять ради раннего вывода данных. Здесь пока нет доказанного безопасного
изменения этого пути.

## Подготовленная локальная правка

`createJournalStore()` получил необязательный локальный `saveJournalEntries()`.
`script.js` использует его в student import, включая повторное получение снимка;
у репозитория без этого метода остаётся прежний fallback. Метод заранее
нормализует весь вход, сохраняет последнюю запись каждой пары урок/ученик, один
раз удаляет старые сущности целевых пар и один раз сохраняет обновлённый документ.
Общие работы уроков и итоговые записи остаются нетронутыми. Прежняя одиночная
операция использует старый путь удаления, её поведение не менялось.

Новая проверка результата сравнивает пакетный и поштучный импорт всех полей
(кроме различающегося времени операции), пары одинаковых оценок, pass/fail,
материалы/endpoint, посещение, чужие пары, миграции v2/legacy, ошибку хранения,
пустой массив, некорректный элемент и последующее одиночное изменение.
Schema/storage IDs и HTTP-контракт прежние. Teacher-mode UI и его вызовы не менялись.
372 теста, lint, format:check и cloud build прошли. Это пока локальное изменение.

Встроенный Chromium, повторный запуск 1080 уроков с уже заполненным локальным
документом: импорт **12,8 мс** вместо **8305,7 мс**; готовность DOM после init
**411,3 мс** вместо **8701,9 мс**. Загруженные модули готовы за 82,2 мс, данные —
за 160 мс. Это одиночное сравнение локальных прогонов, не обещание такого же
коэффициента на реальном iPhone или сети production. На всём запуске осталось
97 чтений документа (включая рендер), запись одна, длина её строки 562126 единиц.
В дополнительном последовательном сравнении сохранённых сборок на том же
заполненном документе DOM готов за 8090,7 мс до правки и 421,5 мс после;
видимый текст ученического дневника совпал. Кнопка копирования короткого отчёта
проверена на наличие в измерительном экране.

### Ручная проверка на iPhone, 27 октября

Пользователь прислал результаты двух запусков того же локального стенда:

| 1080 уроков          | До, мс | После, мс |
| -------------------- | ------ | --------- |
| Модули готовы        | 403    | 106       |
| Данные готовы        | 449    | 133       |
| Импорт журнала       | 685    | 3         |
| DOM готов после init | 1244   | 244       |

Записей в хранилище: **1080 → 1**. Время до готовности DOM уменьшилось примерно
на 80%, но загрузка модулей также различалась: весь выигрыш нельзя приписывать
только пакетному импорту. Это два пользовательских замера синтетического local-only
сценария, а не измерение облачной синхронизации, LCP или физической отрисовки.

Для проверки на iPhone сохранены до/после страницы в отдельной игнорируемой
сборке: `/before-36.html#diary` и `/after-36.html#diary` на измерительном сервере 5175. Они используют один и тот же синтетический снимок и одинаковый local-only
путь без Supabase. Сначала открыть и перезагрузить «до», затем «после»; кнопка
«Скопировать короткий отчёт» сохраняет только числовые этапы, сторону сравнения и
число уроков. Сравнивать именно повторные открытия одного набора. Стенд содержит
профильные маркеры и не предназначен для публикации.
