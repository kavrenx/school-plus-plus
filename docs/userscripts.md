# Подключение Safari через Userscripts

Сборка выпускает `schoolpp.user.js` версии 1.0.1 и страницу
`userscripts-setup.html`. Тестовые установщики и страница Команды в production
не выпускаются.

## Пользовательский путь

При первом входе на телефоне сначала появляется вопрос «Ваш дневник —
e-schools.by?». После «Да» на iPhone/iPad показывается краткая инструкция
Userscripts с десятью скриншотами. «Нет» позволяет оставить заявку на другой
дневник. Готовые QR-ссылки по-прежнему сразу открывают ввод кода.
«Другой способ подключения» открывает карточки
Userscripts, «Через компьютер» и «Расширение». Выбора типа устройства нет.
Для расширения доступны опубликованные магазины Chrome и Firefox.
Ссылка с кодом и QR сразу открывает
ввод кода. Прямой адрес `#connect/methods` восстанавливает карточки после
перезагрузки, даже если в браузере уже был завершён вход.

Пользователь один раз устанавливает и открывает Userscripts, разрешает работу
в Safari и добавляет готовый скрипт. Код открывается в отдельной вкладке,
инструкция остаётся доступна. Перед кнопкой — напоминание прочитать пункты 7–10.
«Синхронизировать и войти» плавно скрывает инструкцию и открывает отдельную
страницу `userscripts-sync.html`, чтобы Safari мог запустить только что
установленный скрипт. Она показывает проверку расширения и открытие госдневника.
Проверка установки свёрнута в «Нужна помощь?», технический отчёт убран
из обычной страницы. Отсутствие
скрипта до установки не показывает ошибку на основном экране.
Кнопка подключения открывает госдневник
в той же вкладке; вход выполняется только там. На странице виден прогресс,
доступны повтор и отмена/возврат. Если перед началом подтверждена сохранённая
копия текущего пользователя, на плашке есть «Открыть без синхронизации».
Отмена сбора не может заменить эту копию поздним результатом.
Полный результат возвращается сразу на экран «Финальные штрихи…», затем после
сохранения и проверки сеанса появляются зелёная галочка и «Готово!». Через
полсекунды после завершения анимации открывается дневник. При ошибке — красный
крест, описание, возврат к настройке; при наличии копии можно открыть её.
Ошибки сохранения на сервер не показываются как успешное облачное сохранение.

Данные сначала валидируются и сохраняются в браузере, затем отправляются
в существующее хранилище School++ через авторизованный сеанс владельца.
История изменений использует тот же репозиторий, что и расширение. Пароли и
токены госдневника не передаются в School++ и не сохраняются в GM storage.
Новых SQL-миграций для этого пути нет.

## Состояния и ограничения

- Пользовательский скрипт имеет отдельный протокол и GM-ключи. Тестовый скрипт
  не может ответить вместо обычного или забрать его результат.
- Неполный сбор и ошибка хранилища не заменяют сохранённый дневник. Кэш
  проверяется по идентификатору текущего сеанса, другой сеанс его не получает.
- Смена владельца проверяется перед импортом и непосредственно перед upsert.
- Уже подключённое по коду устройство имеет права чтения. Новый путь
  требует сначала отключить эту связь на основном устройстве; тихого
  переключения владельца или записи в чужой дневник нет.
- Если сервер не подтвердил сохранение, локальная копия доступна, а отправка
  остаётся ожидающей. Есть отдельный повтор без повторного сбора. Сетевые
  операции ограничены по времени, upsert получает AbortSignal.
- Обычный кэш не удаляется через семь дней. Новое открытие вкладки запускает
  синхронизацию, обычная перезагрузка её не дублирует. Возврат из синхронизации
  отмечается в sessionStorage и не запускает её по кругу.
- Через 15 минут без новой синхронизации или явного открытия сохранённой копии
  запускается обновление, включая вкладку с открытым полем или карточкой предмета.
  В скрытой вкладке переход отложен до её появления. Приостановленный браузером
  таймер проверяет реальное прошедшее время при возвращении в Safari.
- Если Safari восстанавливает прежнюю вкладку как reload без нового сеанса
  навигации, сайт не может отличить это от ручной перезагрузки. Работает таймер
  15 минут. Восстановление back/forward без недавней попытки считается входом.
- Ручная кнопка «Синхронизировать снова» находится в профиле под «Мои устройства».
  Плашки обновления над дневником нет. Подтверждение облачного сохранения при
  необходимости показывается только в профиле.
- Текущий мобильный просмотр сохраняет прежнее ограничение скачивания
  вложений госдневника: для него требуется отдельный транспорт обновления
  короткоживущих ссылок. Синхронизация отметок, ДЗ, расписания и итогов готова
  к проверке; не считать мобильные вложения подтверждённой функцией выпуска.

## Локальная проверка и выпуск

`schoolpp.user.js` всегда выдаётся только с production-адресами, в том числе
локальным dev-сервером. Локальная проверка сохранена в отдельном тестовом
установщике, не выпускаемом в production. Его LAN origin берётся из
VITE_PAIRING_ORIGIN и проверяется. Перед обычным подключением выключить
старые «School++ — тест на iPhone» и «School++ — проверка запуска», установить
«School++ — синхронизация дневника».

Production-артефакт содержит только School++, www.schoolpp.com и
diary.e-schools.by, без LAN/localhost. После публикации локальный установщик
нужно заменить файлом с schoolpp.com. Проверить на телефоне: установку,
возврат с результатом, ФИ/класс, несколько периодов и предметов, повторное
открытие, ручное обновление, отказ сервера и путь по коду.

Для проверки новых поведения и извлечения имени нужно обновить установленный
скрипт до 1.0.1. Название прежнее, повторная установка файла обновляет его.
Сборщик теперь пробует текст страницы, если заголовок содержит только подпись
без имени, и не отсекает дневник из-за пункта «Текущие уроки» в навигации выше.
Форматирование класса устраняет повтор буквы, в том числе для class_number=8Б
и label=Б. Остальная логика извлечения учебных данных не менялась.

## Изображения инструкции

Скриншоты пользователя перенесены из временной папки в
`assets/userscripts-guide/step-01.jpg` … `step-10.jpg`, без изменения содержания.
Все десять занимают около 600 КБ, загружаются лениво, с заданными размерами,
сохраняют пропорции на телефоне и компьютере. Разметка инструкции общая для
основного экрана подключения и `userscripts-setup.html` (`js/userscripts-guide.js`).
Иконка Userscripts — оригинальное изображение из его страницы App Store,
сохранённое как `assets/userscripts-icon.webp`.
