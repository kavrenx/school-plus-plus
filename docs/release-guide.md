# Выпуск School++ 1.0.0

Этот порядок позволяет сначала поднять серверную часть и сайт, затем отправить
расширения на проверку, а после одобрения добавить ссылки магазинов на первый
экран School++.

## 1. Защитить аккаунты

Перед публикацией включите двухэтапную проверку в GitHub, Cloudflare, Supabase,
Google, Microsoft и Mozilla. Коды восстановления сохраните отдельно от Authy.
Пароли должны быть уникальными. Database password, `service_role`, секретные
ключи и коды восстановления нельзя добавлять в GitHub или поля `VITE_*`.

## 2. Подготовить Supabase

1. Откройте проект `schoolpp`.
2. В **Authentication → Providers** включите **Anonymous Sign-Ins**.
3. Убедитесь, что таблица `diary_snapshots` уже создана миграцией
   `supabase/migrations/202609150001_personal_diary.sql`.
4. В **SQL Editor** создайте новый запрос, вставьте содержимое
   `supabase/migrations/202609200001_support_chat.sql` и один раз нажмите
   **Run**.
5. В **Authentication → Users** создайте пользователя
   `support@schoolpp.com`, задайте уникальный пароль и включите подтверждение
   адреса при создании.
6. Выполните SQL из `docs/supabase.md`, который добавляет этого пользователя в
   `support_agents`.
7. В **Table Editor** проверьте, что RLS включён у `diary_snapshots`,
   `support_agents`, `support_conversations` и `support_messages`.
8. В **Authentication → URL Configuration** укажите
   `https://schoolpp.com` как Site URL.

Проверка: вход на `/support.html` с логином `support` должен открыть список
обращений. Пароль вводится только на этой странице и не хранится в репозитории.

## 3. Финальная локальная проверка

В PowerShell:

```powershell
cd D:\school++
npm.cmd ci
npm.cmd test
npm.cmd run lint
npm.cmd run format:check
npm.cmd run build
npm.cmd run extension:package
```

Ожидаемый результат: все тесты зелёные, сборка сайта находится в `dist`, а два
архива расширения — в `.extension-dist`.

## 4. Контрольный коммит

После просмотра изменений создать один релизный коммит:

```powershell
git status
git add .
git commit -m "Prepare School++ 1.0.0 release"
git push origin main
```

Перед `git commit` ещё раз убедитесь, что `.env`, `.env.local`, архивы из
`.extension-dist` и любые пароли не появились в `git status`.

Тег создаётся только после успешной проверки опубликованного сайта:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

## 5. Развернуть сайт в Cloudflare Pages

1. Откройте **Cloudflare Dashboard → Workers & Pages**.
2. Выберите **Create application → Pages → Import an existing Git repository**.
3. Подключите GitHub и выберите `kavrenx/school-plus-plus`.
4. Production branch: `main`.
5. Root directory: `/` или оставить пустым.
6. Build command: `npm run build`. Cloudflare работает на Linux, поэтому здесь
   используется `npm`, а не локальный `npm.cmd`.
7. Build output directory: `dist`.
8. Добавьте production variables:

```text
NODE_VERSION=22.12.0
VITE_APP_MODE=cloud
VITE_SUPABASE_URL=https://PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

9. Нажмите **Save and Deploy**.
10. Сначала проверьте выданный адрес `*.pages.dev`.

`VITE_SUPABASE_PUBLISHABLE_KEY` является браузерным ключом. Database password,
secret key и `service_role` здесь использовать нельзя.

## 6. Подключить домен

1. В проекте Pages откройте **Custom domains → Set up a domain**.
2. Добавьте `schoolpp.com`. Поскольку домен уже находится в Cloudflare, нужная
   DNS-запись должна создаться автоматически.
3. Добавьте `www.schoolpp.com` и настройте постоянный редирект на
   `https://schoolpp.com`, чтобы существовал один основной адрес.
4. Дождитесь статуса Active и сертификата HTTPS.

Не создавайте CNAME вручную до добавления домена через раздел Pages: Cloudflare
предупреждает, что иначе адрес может отвечать ошибкой 522.

## 7. Проверить production

Проверять нужно в обычном окне и в отдельном чистом профиле браузера:

1. `https://schoolpp.com` открывается по HTTPS.
2. Первый экран правильно определяет компьютер и браузер.
3. `https://schoolpp.com/privacy.html` открывается.
4. `https://schoolpp.com/support.html` открывается, а оператор входит только со
   своим паролем.
5. Локально установленное расширение видит production-сайт.
6. Первая синхронизация переносит имя, класс, четверти, расписание, кабинеты,
   отметки и итоги за один запуск.
7. Обновление данных появляется без ручной перезагрузки School++.
8. Фоновое обновление открывает и закрывает служебные вкладки.
9. «Удалить данные» очищает расширение и запись `diary_snapshots`.
10. После повторного открытия данные загружаются из Supabase.
11. Светлая и тёмная темы, дневник, расписание, итоги и расчёт цели работают.

Только после этой проверки создаётся тег `v1.0.0`.

## 8. Подготовить материалы магазинов

Нужно подготовить без настоящих фамилий, отметок и других данных ученика:

- иконку 128×128 PNG — уже есть в `extension/assets/icon128.png`;
- 2–4 скриншота 1280×800: окно расширения, успешная синхронизация, дневник и
  настройки фонового обновления;
- изображение 440×280 для Chrome и Edge;
- при желании изображение 1400×560;
- адрес сайта `https://schoolpp.com`;
- адрес политики `https://schoolpp.com/privacy.html`;
- адрес поддержки `https://schoolpp.com`;
- отдельный временный аккаунт e.school.by для проверяющих, если магазин его
  запросит. Данные такого аккаунта передаются только через закрытое поле для
  команды проверки.

Не используйте собственный ученический аккаунт на скриншотах или в данных для
проверяющих.

## 9. Текст карточки расширения

**Название:** School++ — синхронизация дневника

**Краткое описание:** Переносит расписание, домашние задания и отметки из
e.school.by в понятный дневник School++.

**Полное описание:**

> School++ переносит доступные ученику данные e.school.by в более удобный
> интерфейс: дневник по неделям, расписание, домашние задания, отметки, итоги и
> статистику по предметам. Для синхронизации пользователь входит в e.school.by
> самостоятельно и нажимает одну кнопку в расширении. Расширение не запрашивает
> и не сохраняет логин, пароль, CAPTCHA, cookies или токены авторизации. После
> первой синхронизации оно может периодически проверять обновления; эту функцию
> можно отключить в настройках. School++ является независимым проектом и не
> представляет e.school.by.

**Единственное назначение для формы магазина:** перенос уже доступных ученику
учебных данных из e.school.by в интерфейс School++ и их фоновое обновление.

Обоснования разрешений и инструкция проверяющему находятся в
`docs/extension-release.md`.

## 10. Chrome Web Store

1. Включите двухэтапную проверку Google Account.
2. Зарегистрируйте Chrome Web Store developer account и оплатите разовый сбор.
3. В Developer Dashboard выберите **Add new item**.
4. Загрузите `.extension-dist/schoolpp-chromium-1.0.0.zip`.
5. Заполните **Store Listing**, **Privacy**, **Distribution** и
   **Test instructions**.
6. В Privacy укажите, что расширение обрабатывает содержимое сайта и сведения об
   ученике исключительно для заявленной синхронизации. Укажите отсутствие
   продажи, рекламы и стороннего использования.
7. Privacy policy URL: `https://schoolpp.com/privacy.html`.
8. На первом выпуске включите **deferred publishing**, чтобы после одобрения
   сначала добавить ссылку магазина в School++.
9. Нажмите **Submit for Review**.

## 11. Microsoft Edge Add-ons

1. Войдите в Partner Center через Microsoft Account и подключите программу
   Microsoft Edge.
2. Создайте новое расширение.
3. Загрузите тот же `schoolpp-chromium-1.0.0.zip`.
4. Заполните Availability, Properties, Privacy и Store listings.
5. Добавьте проверочные инструкции и временный аккаунт при необходимости.
6. Отправьте расширение на сертификацию.

## 12. Firefox Add-ons

1. Войдите в Add-ons Developer Hub через Mozilla Account.
2. Выберите **Submit a New Add-on → On this site**.
3. Загрузите `.extension-dist/schoolpp-firefox-1.0.0.zip`.
4. Пройдите автоматическую проверку.
5. Укажите, что код не минифицирован и находится в читаемом виде внутри архива.
6. Добавьте описание, поддержку и ссылку на политику конфиденциальности.
7. В Notes for Reviewers добавьте порядок синхронизации и временный аккаунт,
   если он необходим.
8. Отправьте версию. Минимальная поддерживаемая версия — Firefox 128.

Brave может устанавливать расширения из Chrome Web Store. Отдельную публикацию
для Opera разумно делать после успешного прохождения основных трёх магазинов.

## 13. Добавить ссылки магазинов

После одобрения скопируйте публичные адреса карточек в `js/release-config.js`:

```js
const EXTENSION_STORE_URLS = Object.freeze({
  chromium: "CHROME_WEB_STORE_URL",
  edge: "EDGE_ADDONS_URL",
  firefox: "FIREFOX_AMO_URL",
});
```

Затем выполнить:

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
git add js/release-config.js
git commit -m "Add extension store links"
git push origin main
```

Cloudflare автоматически соберёт новый deploy. Проверьте ссылки в Chrome,
Edge, Firefox и Brave.

## 14. День запуска

- открыть сайт в чистом профиле каждого браузера;
- установить расширение из магазина, а не из папки разработчика;
- выполнить синхронизацию настоящего тестового аккаунта;
- проверить запись в Supabase и удаление данных;
- проверить обращение пользователя и ответ оператора;
- включить уведомления магазинов о проверке и проблемах;
- не публиковать рекламу проекта до завершения этого короткого smoke-теста.

## 15. Последующие обновления

Для каждого выпуска увеличивайте `version` в обоих manifest-файлах и в
`package.json`, запускайте все проверки, создавайте новые ZIP и загружайте новую
версию в существующие карточки магазинов. Новый выпуск нельзя создавать как
отдельное расширение: иначе пользователи не получат автоматическое обновление.
