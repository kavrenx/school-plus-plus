# Предметная модель School++

Этот документ фиксирует целевую модель данных до подключения backend. Поля `id` стабильны: интерфейс не должен строить связи по имени, названию предмета или позиции в массиве.

## Основные сущности

| Сущность          | Обязательные поля                                                                          | Назначение                                      |
| ----------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| School            | `id`, `name`, `timezone`, `locale`                                                         | Школа и её региональные настройки               |
| AcademicYear      | `id`, `title`, `startsOn`, `endsOn`                                                        | Границы конкретного учебного года               |
| AcademicTerm      | `id`, `academicYearId`, `title`, `startsOn`, `endsOn`, `order`                             | Четверть или другой учебный период              |
| SchoolBreak       | `id`, `type`, `title`, `startsOn`, `endsOn`                                                | Каникулы и другие периоды без занятий           |
| User              | `id`, `schoolId`, `role`, `login`, `firstName`, `lastName`                                 | Учётная запись и роль                           |
| Class             | `id`, `schoolId`, `title`, `classTeacherId`                                                | Учебный класс                                   |
| ClassMembership   | `id`, `classId`, `studentId`, `schoolYear`                                                 | Принадлежность ученика классу в конкретном году |
| Subject           | `id`, `schoolId`, `title`                                                                  | Учебный предмет                                 |
| TeacherAssignment | `id`, `teacherId`, `classId`, `subjectId`, `groupId?`                                      | Право учителя работать с предметом и группой    |
| LessonTemplate    | `id`, `schoolYearId`, `classId`, `subjectId`, `teacherId`, `weekday`, `startsAt`, `endsAt` | Повторяющаяся строка расписания                 |
| Lesson            | `id`, `schoolYearId`, `templateId`, `date`, `status`                                       | Конкретное проведённое или отменённое занятие   |
| Homework          | `id`, `lessonId`, `text`, `dueAt?`                                                         | Домашнее задание конкретного урока              |
| GradeEntry        | `id`, `lessonId`, `studentId`, `value`, `authorId`, `createdAt`                            | Одна оценка с автором и временем                |
| AttendanceEntry   | `id`, `lessonId`, `studentId`, `status`, `authorId`, `updatedAt`                           | Отдельный статус посещаемости                   |

| Material          | `id`, `lessonId`, `url`, `title`                                                           | Безопасная ссылка на материал                   |

## Ключевые правила

- Расписание (`LessonTemplate`) не является фактом проведения урока (`Lesson`). Перенос или отмена не меняет шаблон задним числом.
- Оценка, посещаемость, домашнее задание, комментарий и материал — разные сущности. Они не хранятся одним неструктурированным объектом.
- Ученик и учитель связываются с классом и предметом только по идентификаторам.
- Даты уроков хранятся как локальная дата школы `YYYY-MM-DD`, время — как `HH:mm`, часовой пояс берётся из `School.timezone`.
- «Сегодня» вычисляется по часовому поясу школы, а не по часовому поясу устройства ученика или учителя.
- Учебный год и каникулы задаются явными границами; интерфейс не угадывает каникулы только по номеру месяца.
- Четверть задаётся отдельным диапазоном `AcademicTerm`; журнал показывает только занятия выбранного предмета внутри этого диапазона.
- Каждое изменение оценки и посещаемости в production имеет автора и время.
- Пароль не относится к профилю пользователя и никогда не возвращается клиенту из repository/API.

### Проведение урока и посещаемость

- Учитель не подтверждает проведение урока отдельной обязательной кнопкой.
- Пока в занятии нет ни одной содержательной записи, оно остаётся нетронутым, а посещаемость всех учеников — «Не отмечено», даже если время урока уже прошло.
- Оценка, отсутствие, замечание, домашнее задание или материал считаются работой учителя с занятием.
- Если в занятии есть такая работа и время окончания прошло, занятие считается обработанным. Ученик без явной `Н` считается присутствовавшим.
- До окончания обрабатываемого занятия присутствие выводится только для ученика, которому уже поставлена оценка или написано замечание. Остальные остаются неотмеченными.
- Явная `Н` всегда имеет приоритет над вычисленным присутствием и не сочетается с оценкой.
- Состояние вычисляется из даты, времени и записей, поэтому не зависит от работающего в фоне таймера и корректно восстанавливается после обновления страницы.

## Контракты репозиториев

Контроллеры получают зависимости извне и не знают, используется `localStorage` или сервер:

```text
users:    saveUser, clearUser, getSavedUser, getProfile, saveProfile, clearProfile
avatars:  get, save, remove
journal:  getJournalEntry, getLessonEntries, getLessonWork, getTermGrade,
          getTermGrades, saveJournalEntry, saveLessonWork, saveTermGrade,
          mergeLessonForStudent
```

`createDemoRepositories` собирает текущие локальные реализации. Будущая API-версия должна предоставить те же возможности, но возвращать асинхронные результаты и серверные ошибки через единый слой приложения.

Обязательные методы проверяются модулем `repository-contracts`. Для журнала уже существуют обе реализации: локальная `createJournalStore` и серверная `createApiJournalRepository`; HTTP-правила описаны в `docs/repository-contracts.md`.

## Переход от текущего demo

1. Сохранить совместимость текущих экранов через репозитории.
2. После выбора backend расширить готовый API-подход журнала на сессию и профиль без изменения разметки экранов.
3. При подключении backend сохранить уже реализованную привязку домашнего задания и общих материалов к уроку, а четвертной отметки — к ученику, назначению учителя и учебному периоду.

## Реализовано в нормализованной модели v4

- У школы есть стабильный `schoolId`, который наследуют пользователи, классы, ученики, предметы, группы и назначения учителей.
- Повторяющийся слот хранится в `lessonTemplates`, а конкретные уроки — в `lessons`.
- У конкретного урока есть `templateId`, локальная дата `date` и состояние `status`.
- Учебный год содержит нормализованные `terms`; модель умеет находить четверть по локальной дате урока.
- `teacher-journal-model` отдельно вычисляет состояние работы с уроком и выводимый статус посещаемости.
- Учительский журнал получает занятия только для выбранных класса, предмета, группы и четверти.
- В demo запланированные занятия четверти разворачиваются из `LessonTemplate`; уже существующее конкретное занятие с той же датой и шаблоном имеет приоритет. В production конкретные занятия возвращает сервер.
- Прежний `lesson.id` сохранён без изменений, поэтому локальные записи журнала продолжают работать.
- Локальное хранилище журнала имеет `schemaVersion: 3`: ученические записи разделены на оценки, посещаемость и замечания; `lessonWorkEntries` хранит общее домашнее задание и материалы урока, а `termGradeEntries` — четвертные отметки.
- Старый составной объект журнала автоматически мигрирует в эти коллекции при первом чтении без смены `lessonId` и потери данных.
- Каждая новая сущность журнала получает стабильный идентификатор, автора изменения и время обновления.
- Старые домашние задания и материалы со строки ученика читаются для совместимости, а новые значения сохраняются на уровне урока и одинаково показываются всем ученикам.
- Недели, шаблоны расписания и уроки связаны с `schoolYearId`; арифметика календарных дат выполняется без UTC-сдвигов.
- Полные правила даты и времени зафиксированы в `docs/date-and-time.md`.
