# iPhone/iPad: проверка Команд Safari

Состояние: проверка чтения пройдена на реальном iPhone; полный сбор и локальный
просмотр готовы к проверке пользователем. **Облачный импорт пока не подключён**. В опубликованном сайте
основным остаётся подключение по коду. Локально iPhone/iPad показывает вход
в тестовую инструкцию `ios-setup.html`; QR с кодом сразу открывает форму кода.
Android использует подключение по коду.

## Первый тест на реальном устройстве

Открыть `/ios-setup.html` на телефоне и создать Команду из трёх действий:

1. «Выполнить JavaScript на веб-странице»: вход — Safari webpage из меню
   «Поделиться», скрипт скопировать с инструкции.
2. «Скопировать в буфер обмена»: результат JavaScript.
3. «Показать результат»: результат JavaScript.

Включить запуск из меню «Поделиться» только для веб-страниц Safari и разрешение
сценариев в настройках Команд. Войти в госдневник через Safari, переключить
неделю, запустить Команду через «Поделиться». Один URL или запуск установленной
Команды через `shortcuts://` не заменяет вход Safari webpage.

Отчёт `schoolpp-ios-probe-v1` содержит статусы, количество доступных недель,
уроков, отметок и ДЗ. Содержимое ответа, ФИО, тексты ДЗ, значения отметок,
адреса с идентификаторами и данные входа не возвращаются. Загрузка в School++
не выполняется. Скрипт делает только GET к точному origin госдневника;
переходы HTTP запрещены. Сначала проверяет текущие cookies, затем при 401/403
пробует доступный локально токен сессии. Этот токен остаётся в текущем запуске
и используется только для запросов к тому же госдневнику.

Общий лимит теста 4,2 секунды, отдельного запроса — 1,1 секунды. Это наши
ограничения, не гарантии Apple. При медленном соединении возможен таймаут;
он сам по себе не означает невозможность метода. Apple также ограничивает
длительность JavaScript-действия, и iOS может завершить его раньше отчёта.

## Следующий этап после проверки

Первый тест на iPhone получил HTTP 200 для уроков, года и списка 36 недель
за 248 мс. Авторизация сработала со второй попытки. Ноль отметок в первом
отчёте не доказывает отсутствие отметок в API: счётчик учитывал только
`lesson_marks`; теперь поддерживает и одиночные/альтернативные поля.

## Второй тест: полный сбор и локальный просмотр

На той же странице кнопка второго этапа копирует скрипт с `collect: true`.
Остальные действия Команды не меняются. Результат `schoolpp-ios-export-v1`
**содержит личный дневник**. Его нужно вставить в форму на странице настройки,
а не отправлять в чат. Разбор и адаптация выполняются локально. Кнопка
«Скопировать короткий отчёт» возвращает только разрешённые счётчики и статусы.

Сбор читает все недели (до 60), четверти/каникулы, звонки, расписание, предметы,
учителей, класс и итоговые отметки через фиксированные GET endpoints. Не более
четырёх запросов одновременно; общий срок 8,2 секунды, запрос — 1,8 секунды.
Текущая неделя повторно не загружается. Если неделя или четверти не получены,
экспорт снимка не выполняется. Остальные необязательные ответы отражаются
в отчёте; отсутствующее расписание показывается как ограничение точности.

Снимок совместим с существующим адаптером. Заголовок профиля извлекается
отдельно от «Текущие уроки», без полного текста страницы. Заголовки запросов,
браузерные ресурсы и хранилища в снимок не включаются; неожиданные поля
авторизации и JWT из API дополнительно удаляются. До отправки результата
проверяется лимит 1,8 МБ. Дополнительные запросы вложений пока не выполняются.

«Открыть тестовый дневник» работает только в DEV. Данные передаются следующей
странице через sessionStorage той же вкладки на 30 минут. Облачное чтение,
сохранение и фоновые обновления дневника в этом режиме отключены. История
изменений и журнал используют память, существующее подключение не меняется.
Обновление страницы сохраняет просмотр до истечения срока; закрытие вкладки
удаляет временный результат. В релизной сборке вход в этот режим выключен.

## Дальнейшая работа после второго теста

- Подтвердить полный сбор и отображение на реальном iPhone.
- Для длинной загрузки рассмотреть короткий JS-шаг и HTTP-действия Команды;
  перенос авторизации между ними пока не проверен.
- Подготовить привязанный к пользователю приём данных с одноразовым доступом;
  не передавать токены госдневника в School++.
- Получить настоящую ссылку iCloud на готовую Команду с Apple-устройства.
  Установочного файла или ссылки на готовую Команду сейчас нет.
- Только после полного теста включить Команду как основной способ на iOS.

Автоматический запуск не создаёт Safari webpage и не гарантирует чтение
авторизованной страницы в фоне. Пока доступен только ручной тест из Safari.
